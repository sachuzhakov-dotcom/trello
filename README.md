# Доска задач (Trello-клон)

Полноценное приложение: бэкенд на Node.js/Express + фронтенд на чистом HTML/CSS/JS.
Данные хранятся в файле `data.json` рядом с сервером — никакой отдельной СУБД ставить не нужно.

## Запуск

```bash
npm install
npm start
```

Откройте в браузере: **http://localhost:3000**

По умолчанию сервер слушает порт 3000. Изменить можно переменной окружения `PORT`:

```bash
PORT=4000 npm start
```

## Структура проекта

```
trello-clone/
├── server.js        # Express-сервер и REST API
├── data.json         # хранилище данных (создаётся автоматически при первом запуске)
├── package.json
└── public/            # фронтенд (отдаётся сервером как статика)
    ├── index.html
    ├── styles.css
    └── app.js
```

## REST API

| Метод  | Путь                         | Описание                              |
|--------|------------------------------|----------------------------------------|
| GET    | /api/state                   | Получить всё состояние доски          |
| PATCH  | /api/title                   | Переименовать доску `{ title }`       |
| POST   | /api/columns                 | Создать колонку `{ name }`            |
| PATCH  | /api/columns/:id             | Переименовать колонку `{ name }`      |
| DELETE | /api/columns/:id             | Удалить колонку (и её карточки)       |
| POST   | /api/cards                   | Создать карточку `{ columnId, title }`|
| PATCH  | /api/cards/:id                | Изменить карточку `{ title, desc, label }` |
| DELETE | /api/cards/:id                | Удалить карточку                      |
| POST   | /api/cards/:id/move           | Переместить в другую колонку `{ columnId }` |

## Публикация на GitHub

В проекте уже есть всё нужное: `.gitignore` (исключает `node_modules` и `data.json`, чтобы в репозиторий не попадали чужие/локальные данные), `LICENSE` (MIT — при желании поменяйте владельца в файле) и CI-проверка в `.github/workflows/ci.yml`, которая при каждом пуше ставит зависимости и проверяет синтаксис на Node.js 20 и 22.

1. Создайте пустой репозиторий на GitHub (без README/лицензии — они уже есть в проекте).
2. В папке проекта:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/<название-репозитория>.git
   git push -u origin main
   ```
3. Готово — репозиторий на GitHub, из него можно подключать автодеплой в Timeweb App Platform (раздел выше).

## Деплой на Timeweb Cloud

Есть два пути: быстрый через **App Platform** (автодеплой из Git) и классический — через **облачный сервер** (VDS) с полным контролем.

### Вариант 1. App Platform (проще всего)

1. Залейте проект в репозиторий на GitHub/GitLab/Bitbucket.
2. В панели Timeweb Cloud: **App Platform → Создать приложение → Backend-приложение**.
3. Подключите репозиторий, выберите рантайм **Node.js** (версия 20/22/24) и рабочую директорию (корень репозитория, где лежит `package.json`).
4. Timeweb сам определит `server.js` как точку входа и запустит его через PM2 — ничего вручную настраивать не нужно.
5. Порт передаётся через переменную окружения `PORT`, которую сервер уже читает (`process.env.PORT`), а слушает `0.0.0.0` — оба требования App Platform выполнены.
6. После деплоя приложение будет доступно по выданному Timeweb домену (или своему, если подключите его в настройках приложения).

**Важный нюанс.** App Platform — это контейнерная платформа: локальная файловая система (а значит и `data.json`) не гарантированно переживает пересборку/редеплой контейнера. Для тестов и демо это не критично, но для продакшена лучше вынести хранение данных из файла в управляемую БД Timeweb (PostgreSQL/MySQL) — если нужно, могу переписать `server.js` под PostgreSQL.

### Вариант 2. Облачный сервер (VDS) — данные точно не потеряются

1. Создайте облачный сервер с Ubuntu в панели Timeweb Cloud.
2. Подключитесь по SSH и поставьте Node.js и PM2:
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
   sudo apt install -y nodejs
   sudo npm install -g pm2
   ```
3. Скопируйте проект на сервер (`git clone` вашего репозитория или `scp` архива) и установите зависимости:
   ```bash
   cd trello-clone
   npm install
   ```
4. Запустите через PM2 (переживает перезагрузку сервера, автоперезапуск при падении):
   ```bash
   pm2 start server.js --name kanban
   pm2 save
   pm2 startup   # выполнить команду, которую выведет pm2
   ```
5. (Рекомендуется) Поставьте Nginx как reverse proxy на 80/443 порт перед приложением и подключите домен с SSL через certbot:
   ```bash
   sudo apt install -y nginx
   ```
   В конфиге сайта `proxy_pass http://127.0.0.1:3000;` — и приложение будет доступно по обычному домену без указания порта.

В этом варианте `data.json` лежит на постоянном диске сервера и не пропадёт между деплоями.

## Возможные улучшения

- Несколько независимых досок вместо одной
- Авторизация пользователей и совместная работа в реальном времени (WebSocket)
- Сохранение позиции карточки внутри колонки при перетаскивании (сейчас карточка всегда попадает в конец колонки)
- Переход с `data.json` на настоящую БД (SQLite/PostgreSQL) при росте нагрузки
